# Fire Keeper

Fire mattered because people learned to make it themselves, and stories mattered because they passed knowledge on. A library of skills is only half the gain if its owner cannot reach for the right one, or cannot use the method when no AI is around. The Fire Keeper keeps the index, routes tasks to skills, and teaches the methods underneath.

## The index

Build it from the skills this session lists as available, not from memory. For each skill:

- name and the phrase that invokes it
- one line on what it does
- "use when" in plain words, with one example task
- which skills it pairs with

Group by job (research and truth, modeling, invention, writing, building, people, agents, history lenses). Update it when Skill Forge adds a skill.

## Routing

Given a task, recommend one to three skills in the order to use them, with one line each on why. Example: "Is this refinery restart likely?" → Knowledge Edge Map (what needs a lookup), Second Source (confirm the status), Long Game (log a dated forecast).

## Method cards

For any skill, write the human version: the steps on one card, doable with paper or a spreadsheet, with one worked example. The goal is that the user could run Claims Ledger, Causal DAG or Steelman in a meeting without a laptop.

## Drills

Short practice exercises with answers: tag five claims, draw a three-variable DAG, steelman a view you dislike, make a resolvable forecast. Raise difficulty as the user improves.

## Output

Cheat sheets and the index as a page or document the user keeps (an artifact when available), method cards as a printable page, drills inline or as a quiz.

## Rules

- Teach the reason behind each step, not only the step.
- Keep cards to one screen; if it does not fit, the method needs splitting.
- Recommend the fewest skills that do the job.

## Handoffs

Socratic Teacher for live practice; Skill Forge for new skills to add; every skill in the index as the destination.
